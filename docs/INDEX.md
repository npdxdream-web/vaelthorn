## Living doc vs. Snapshot — แก้ต่อได้ vs. อ่านอย่างเดียว

**Living docs (แก้ต่อเนื่องได้ตามงานจริง):**
- `CLAUDE.md` — อัปเดตทุกครั้งที่ schema/route/convention เปลี่ยน
- `CHANGELOG.md` — เพิ่ม section ใหม่ต่อท้ายทุกครั้งที่มีงานสำคัญจบ (อย่าลบของเก่า)
- `roadmap.md` — ติ๊ก `[x]` เมื่อฟีเจอร์เสร็จจริง, เพิ่มรายการใหม่ได้

**Snapshots (จุดเวลาใดเวลาหนึ่ง — แก้ได้แค่เพื่อ mark ว่า resolved แล้ว ห้ามรีไรท์เนื้อหาเดิม):**
- `audits/*.md` — 1 ไฟล์ต่อ 1 รอบ QA audit ตั้งชื่อด้วยวันที่ (`YYYY-MM-DD-*.md`) รอบใหม่ = ไฟล์ใหม่ ไม่ทับไฟล์เก่า
- `plans/*.md` — 1 ไฟล์ต่อ 1 ฟีเจอร์ที่วางแผนไว้ก่อนสั่งให้ Claude Code ทำ อัปเดตส่วน "สถานะจริงหลังทำเสร็จ" ได้ แต่ส่วนแผนเดิมเก็บไว้เป็น record
- `archive/*.md` — ห้ามแก้เลย เก็บไว้อ่านอ้างอิงประวัติศาสตร์เท่านั้น

## โครงสร้างโฟลเดอร์นี้

```
docs/
├── INDEX.md              ← ไฟล์นี้
├── CHANGELOG.md           ← living: session log ตามลำดับเวลา
├── roadmap.md             ← living: checklist ฟีเจอร์เสร็จ/ค้าง
├── frontend-setup.md      ← วิธีติดตั้ง frontend (npm install/dev/build)
├── plans/                 ← snapshot: แผนออกแบบฟีเจอร์ (1 ไฟล์ต่อ 1 ฟีเจอร์ ก่อนเริ่มสร้างจริง)
│   └── event-thread-ux.md
├── audits/                ← snapshot: ผล QA audit แต่ละรอบ (ตั้งชื่อด้วยวันที่)
│   └── 2026-07-29-qa-audit.md
└── archive/               ← ห้ามแก้: log ประวัติศาสตร์ที่ถูกแทนที่แล้ว
    └── dev-progress-2026-06-19.md
```

## ไฟล์ที่ยังอยู่ที่ root โดยตั้งใจ (ไม่ย้ายเข้ามาที่นี่)

- `/README.md` — GitHub landing page, ต้องอยู่ที่ root ตามธรรมเนียม
- `/CLAUDE.md` — Claude Code ต้องเจอไฟล์นี้ที่ root โดยอัตโนมัติ

## เกี่ยวกับ `design-reference/`

โฟลเดอร์ `design-reference/` ที่ root เก็บไฟล์ export จาก Figma/AI design tool
(shadcn/ui component kit ดิบๆ, mockup zip/png) ที่**ไม่มีโค้ดจริงในระบบอ้างอิงถึงเลย**
— เก็บไว้เผื่อยังต้องใช้อ้างอิงภาพ ไม่ใช่ source code ที่ใช้งานจริง ถ้ายืนยันว่าไม่ต้องการ
แล้วสามารถลบทั้งโฟลเดอร์ได้โดยไม่กระทบแอปเลย
