## 🔴 ฝั่งแอดมิน (Admin Panel / Filament)

### 1. [พังหนัก] สร้าง Event ไม่ได้เลยสักประเภทเดียว — `created_by` ไม่ถูกกรอกอัตโนมัติ
**พบที่**: `/admin/events/create` (ทดสอบทั้ง 4 ประเภท: Flash, Location, Story Arc, Crisis — พังเหมือนกันหมด)
**ทำอะไรแล้วเกิดอะไรขึ้น**: กรอกฟอร์มสร้าง Event ครบถ้วนถูกต้อง (title, type, kingdom, exp_reward ที่ผ่าน validation แล้ว) แล้วกด Create → เจอ SQL error ทันที: `NOT NULL constraint failed: events.created_by` การสร้าง Event ล้มเหลว 100% ไม่มีทางเลี่ยง
**ควรจะเกิดอะไรขึ้น**: `events.created_by` ควรถูกกรอกอัตโนมัติเป็น admin ที่ล็อกอินอยู่ตอนกด Create (CLAUDE.md เขียนไว้ว่า "created_by auto-set in CreateEvent page" แต่ในโค้ดจริง `CreateEvent.php` ไม่มี logic นี้เลย — ฟอร์มก็ไม่มีฟิลด์นี้ให้กรอกเองด้วย)
**ความรุนแรง**: 🔴 พังหนัก — ฟีเจอร์หลักที่แอดมินต้องใช้สร้างเนื้อหา event ทั้งระบบใช้งานไม่ได้เลยแม้แต่ครั้งเดียว

### 2. [พังหนัก] แก้ไข/เพิ่มไอเทมในคลังตัวละครจากหลังบ้านไม่ได้ — อ้างคอลัมน์ที่ถูกลบไปแล้ว
**พบที่**: `CharacterResource` → แท็บ "ไอเทม" (InventoryRelationManager) และ `/admin/inventories` (InventoryResource)
**ทำอะไรแล้วเกิดอะไรขึ้น**: ทั้งฟอร์มสร้าง/แก้ไขและคอลัมน์ในตารางอ้างถึง `item_name` ซึ่งถูกลบออกจากตาราง `inventories` ไปนานแล้ว (แทนที่ด้วย `item_id` FK→items) กด Create/Edit จะพัง (SQL error "unknown column"); รายการที่แสดงในตารางจะไม่มีชื่อไอเทมโชว์เลย (ค่าว่างตลอด เพราะ Eloquent อ่าน attribute ที่ไม่มีจริงได้ค่า null เงียบๆ ไม่ error)
**ควรจะเกิดอะไรขึ้น**: ควรใช้ dropdown เลือก `item_id` จาก `items` table แทน (ตรงกับที่ `Inventory::$fillable` ใช้จริง)
**ความรุนแรง**: 🔴 พังหนัก — แอดมินไม่มีทางแก้ไขคลังไอเทมของผู้เล่นรายตัวจากหลังบ้านได้เลย (นี่คือบั๊กเดิมที่เคยพบและบันทึกไว้ใน docs/CHANGELOG.md เมื่อ 2026-07-25 ว่า "ยังไม่ได้แก้" — ยืนยันแล้วว่ายังพังเหมือนเดิม)

### 3. [ใช้งานได้แต่ไม่สมบูรณ์] คอลัมน์ "ผู้เขียน" ในตารางกระทู้ (หลังบ้าน) ว่างเปล่าตลอด
**พบที่**: `/admin/threads` (ThreadResource) — คอลัมน์ `user.name`
**ทำอะไรแล้วเกิดอะไรขึ้น**: `Thread` model ไม่มี relation ชื่อ `user()` (มีแต่ `creator()`/`author()`) คอลัมน์นี้เลยว่างเปล่าทุกแถวเสมอ ไม่ error แค่ไม่มีข้อมูล
**ควรจะเกิดอะไรขึ้น**: ควรใช้ `creator.name` แทน จะได้เห็นว่าใครเป็นคนสร้างกระทู้แต่ละอัน
**ความรุนแรง**: 🟡 ใช้งานได้แต่ไม่สมบูรณ์ — ไม่ทำให้พัง แต่ทำให้แอดมินดูไม่ออกว่าใครโพสต์กระทู้ไหนจากหน้า list

### 4. [จุดเล็กน้อย] ผู้เล่นไม่ได้รับแจ้งเตือนเมื่อกระทู้ถูก reject/ขอแก้ไข — ✅ แก้แล้ว (2026-08-02)
**พบที่**: `ThreadController::moderate()` action `reject` และ `request_edit`
**ทำอะไรแล้วเกิดอะไรขึ้น**: ทดสอบจริง — แอดมิน reject กระทู้ของผู้เล่น พร้อมใส่เหตุผล ระบบบันทึก `moderation_message` ถูกต้อง แต่ไม่มี notification ส่งไปหาผู้เล่นเลย (เช็ค `notifications` table แล้วไม่มีแถวใหม่) ผู้เล่นจะไม่รู้เลยว่ากระทู้ตัวเองถูกตีกลับ จนกว่าจะเปิดกระทู้เข้าไปดูเอง
**ควรจะเกิดอะไรขึ้น**: ควรมี notification แจ้งเตือนเหมือนตอนโพสต์ถูก approve/reject (`notifyPostApproved`/มีเมธอด `notifyPostRejected` เตรียมไว้แล้วในโค้ดด้วยซ้ำ แต่ไม่เคยถูกเรียกใช้งานที่ไหนเลยในทั้งระบบ — เป็นโค้ดที่สร้างไว้ค้างไว้ ไม่ได้เอามาต่อ)
**ความรุนแรง**: 🟢 จุดเล็กน้อย (UX gap ไม่ใช่บั๊กที่ทำให้พัง) — แต่ถ้าแอดมิน reject บ่อยๆ ผู้เล่นจะรู้สึกเหมือนกระทู้หายไปเฉยๆ
**✅ แก้แล้ว**: เพิ่ม `NotificationService::notifyThreadRequestEdit()`/`notifyThreadRejected()` และเรียกใช้ใน `moderate()` แล้ว — commit `b65a49a` (พลอยได้จากงาน Event-Thread เฟส 1, ดู `docs/plans/event-thread-ux.md`)

### 5. [จุดเล็กน้อย] ปุ่ม "Approve" ตัวละครกดได้แม้ยังทำ onboarding ไม่ครบ 3 ด่าน
**พบที่**: `UserResource`/`CharacterResource` — action `approve_character`
**ทำอะไรแล้วเกิดอะไรขึ้น**: เงื่อนไข `->visible()` เช็คแค่ `status === 'pending'` เท่านั้น ไม่เช็คว่า essay ทั้ง 3 ด่านเขียนครบหรือยัง แอดมินสามารถกด Approve ตัวละครที่ยังไม่เขียนอะไรเลยได้ นอกจากนี้ modal confirmation ยังเขียนข้อความหลอกไว้ว่า "จะถูก Approve และเลื่อนเป็น Level 1 ทันที" (ถ้า level ยังเป็น 0) แต่ฟังก์ชัน `approveCharacter()` จริงๆ แค่ set `status='approved'` เท่านั้น ไม่ได้เลื่อน level ให้เลย — ข้อความใน modal ไม่ตรงกับสิ่งที่เกิดขึ้นจริง
**ควรจะเกิดอะไรขึ้น**: ปุ่มควรซ่อน/disable จนกว่าจะครบ 3 ด่าน หรืออย่างน้อย modal ไม่ควรพูดเกินจริงว่าจะเลื่อน level ให้
**ความรุนแรง**: 🟢 จุดเล็กน้อย — เป็น edge case ที่ต้องอาศัยแอดมินกดพลาด ไม่ใช่ path ปกติ

### 6. ยืนยันว่า "ปุ่มใช้ได้จริง" (ไม่ใช่แค่ทำงานได้)
สร้าง/แก้ไข Kingdom, สร้าง City, แก้ไข City, สร้าง Badge — ทดสอบจริงทุกตัวผ่าน Livewire component test แล้ว **ใช้งานได้ปกติทั้งหมด ไม่มีปัญหา**. Approve/Reject โพสต์ (PostResource + หน้ากระทู้จริง) ก็ทำงานถูกต้อง reward เข้าคลังจริง (ดูฝั่งผู้เล่น ข้อ 5)

## 🔵 ฝั่งผู้เล่น (Player Flow)

### 1. [พังหนัก] เปิดหน้ากระทู้ 500 error ทันที ถ้าล็อกอินด้วยบัญชีแอดมิน/มอดที่ไม่มีตัวละคร
**พบที่**: `/threads/{id}` (`thread.blade.php`) — ทดสอบด้วยบัญชี admin ที่สร้างขึ้นมาโดยไม่มี Character (ไม่ได้ผ่านหน้าสมัครสมาชิกปกติ)
**ทำอะไรแล้วเกิดอะไรขึ้น**: เปิดกระทู้ที่มีสถานะ approved/pending/draft/request_edit (เกือบทุกกระทู้ปกติ) → หน้าเว็บ error 500 ทันที ข้อความจริงจาก log: `Attempt to read property "name" on null` ที่บรรทัด `{{ $currentCharacter->name }}` ในส่วน "Posting as" ของฟอร์มตอบกระทู้ — โค้ดสมมติว่าคนที่ล็อกอินอยู่ต้องมีตัวละครเสมอ แต่แอดมิน/มอดไม่จำเป็นต้องมี
**ควรจะเกิดอะไรขึ้น**: ควรใช้ `{{ $currentCharacter?->name ?? 'Admin' }}` (จริงๆ มีโค้ดแบบนี้อยู่แล้วในอีกจุดของไฟล์เดียวกัน บรรทัด "โพสต์ในฐานะ {{ $currentCharacter?->name ?? 'Admin' }}" — แต่จุด "Posting as" ด้านบนไม่ได้ใช้ null-safe แบบเดียวกัน)
**ความรุนแรง**: 🔴 พังหนัก — **หมายเหตุ**: บัญชีแอดมินจริงที่ใช้งานอยู่ปัจจุบัน (2 บัญชี) ทุกบัญชีมีตัวละครอยู่แล้ว จึงยังไม่โดนบั๊กนี้ในปัจจุบัน แต่จะพังทันทีถ้ามีการเพิ่มแอดมิน/มอดคนใหม่โดยไม่สร้างตัวละครให้ (เช่นสร้างผ่าน tinker/seeder) — เป็นระเบิดเวลาที่รอวันเจอ

### 2. [ใช้งานได้แต่ไม่สมบูรณ์] Approve โพสต์ ≠ Approve กระทู้ — ต้องกด 2 ที่แยกกัน ไม่มีอะไรเตือน — ✅ แก้แล้ว (2026-08-02)
**พบที่**: กระทู้ใหม่ในเมืองที่ต้องรออนุมัติ (`require_approval=true`)
**ทำอะไรแล้วเกิดอะไรขึ้น**: ทดสอบจริง — สร้างกระทู้ใหม่ → ทั้งกระทู้และโพสต์แรกมีสถานะ `pending` แอดมิน approve โพสต์ (`/posts/{id}/approve`) แล้ว โพสต์เปลี่ยนเป็น approved จริง **แต่กระทู้ยังเป็น pending อยู่เหมือนเดิม** ทำให้ผู้เล่นคนอื่น (ที่ไม่ใช่เจ้าของกระทู้) มองไม่เห็นกระทู้นี้ในหน้าเมืองเลย ต้องให้แอดมินกด approve กระทู้แยกอีกครั้ง (คนละปุ่ม คนละหน้า) ถึงจะโชว์จริง
**ควรจะเกิดอะไรขึ้น**: อย่างน้อยควรมีการเตือน/ไฮไลต์ให้ชัดว่ากระทู้ยังไม่ approve หลังจาก approve โพสต์แรกแล้ว หรือ approve โพสต์แรกของกระทู้ใหม่ควร auto-approve กระทู้ไปด้วยเลย
**ความรุนแรง**: 🟡 ใช้งานได้แต่ไม่สมบูรณ์ — เสี่ยงที่แอดมินจะกด approve โพสต์แล้วคิดว่าจบแล้ว ทั้งที่เนื้อหายังไม่มีใครเห็นจริง
**✅ แก้แล้ว**: เพิ่ม `ThreadController::autoApproveThreadOnFirstPost()` — approve โพสต์แรกของกระทู้ที่ยัง pending จะ auto-approve กระทู้ไปด้วยในตัว ไม่ต้องกด 2 ที่อีกต่อไป — commit `b65a49a` (พลอยได้จากงาน Event-Thread เฟส 1)

### 3. [จุดเล็กน้อย] โพสต์ในโซนที่ต้องรออนุมัติ (และไม่มี Event ผูกอยู่) จะได้ EXP = 0 เสมอ โดยไม่มีข้อความเตือนล่วงหน้า — ✅ แก้แล้ว (2026-08-02)
**พบที่**: กระทู้/โพสต์ธรรมดาที่ไม่ได้ผูกกับ Event ในเมืองที่ `require_approval=true`
**ทำอะไรแล้วเกิดอะไรขึ้น**: ทดสอบจริง — โพสต์ถูก approve แล้ว แต่ EXP/Gold ไม่เข้าเลย (exp=0, ไม่มี RewardLog ถูกสร้าง) ตรวจโค้ดแล้วยืนยันว่า**ตั้งใจให้เป็นแบบนี้** (มีคอมเมนต์ในโค้ดอธิบายไว้ชัดเจนว่าเป็น "unchanged from pre-existing behavior") ไม่ใช่บั๊ก
**ควรจะเกิดอะไรขึ้น**: พฤติกรรมถูกต้องตามที่ออกแบบไว้ แต่หน้าเว็บไม่มีข้อความบอกผู้เล่นเลยว่า "โพสต์นี้จะไม่ได้ EXP เพราะไม่ได้ผูกกับ Event" — ผู้เล่นเขียนโพสต์เสร็จ รอ approve แล้วไม่ได้อะไรตอบแทน อาจจะงงว่าทำไม
**ความรุนแรง**: 🟢 จุดเล็กน้อย — เป็นเรื่อง UX/ความชัดเจนของข้อความ ไม่ใช่บั๊ก
**✅ แก้แล้ว**: เพิ่มข้อความเตือนสีเหลือง "โซนนี้ต้องรออนุมัติและไม่ได้ผูกกับ Event — กระทู้นี้จะไม่ได้รับ EXP..." ทั้งในฟอร์มสร้างกระทู้ (`thread-create.blade.php`) และหน้ากระทู้ (`thread.blade.php`) — commit `b65a49a` (พลอยได้จากงาน Event-Thread เฟส 1)

### 4. ยืนยันว่า flow หลักทำงานถูกต้องครบวงจร (ทดสอบจริงตั้งแต่ต้นจนจบ)
- สมัครสมาชิก → onboarding 3 essay → แอดมิน approve → บังคับเลือกอาณาจักร → เลือกแล้วกลายเป็น `active` — **ถูกต้องทุกขั้นตอน**
- เขียนกระทู้ในโซน auto-approve → เผยแพร่ทันที → ได้ EXP +1 เข้า `character_stats` จริง → มี `reward_logs` ถูกสร้างถูกต้อง — **ถูกต้อง**
- Notification: ได้รับแจ้งเตือน `level_up` ตอน onboarding เสร็จ, `post_approved` ตอนโพสต์ (ที่ต้องรออนุมัติ) ถูก approve — **ถูกต้อง**
- หน้า Chronicles (`/chronicles`), Chronicle Archive (`/archive`), Notification Center (`/notifications`), Inventory (`/inventory`) — โหลดได้ปกติทุกหน้า ไม่มี error
- หน้าโปรไฟล์ตัวละคร — แสดง Badge ที่ได้รับถูกต้อง, แท็บ "ความสัมพันธ์" (ระบบเพื่อน) แสดงถูกต้อง ปุ่มเพิ่มเพื่อนไม่โผล่ตอนดูโปรไฟล์ตัวเอง (ถูกต้อง)
- Kingdom ที่ `is_active=false` บล็อกการเข้าเมืองจริง แม้จะเป็นบ้านเกิดของตัวเอง (ยืนยันตรงตามที่บันทึกไว้ใน docs/CHANGELOG.md)
